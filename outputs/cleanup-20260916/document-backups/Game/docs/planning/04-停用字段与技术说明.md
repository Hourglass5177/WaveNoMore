## 表格与游戏的连接

读取器：`src/content/rules/planning_parameters.gd`。Excel 是标准 ZIP/XML，用 Godot 自带 `ZIPReader` 和 `XMLParser` 在装载阶段读取数值，不依赖 Excel 进程、Python、宏或额外插件。

读取各参数页中的 H 列对象、I 列字段名、B 列当前值；对象和字段是稳定键，行顺序和页签顺序不参与映射。比例使用 XLSX 中的真实数值；显示百分号不改变读取结果。支持带／不带 XML 命名空间前缀、共享字符串与内联文本。

`content/rules/planning_parameters.json` 描述已开放字段的类型、范围、基线和说明，不是第二份运行时平衡表。当前值来自工作簿；无表时来自已有 `.tres`。数值输入检查及窗口／频率关系检查只在装载发生，不在玩法帧重复执行。

流程：表格保存 → 重新装载 → 复制关卡规则 → 按新规则检查并适配源 Tuning → 编译 → 领域判定、输入转换、音符表现与理想预览共享本局副本。原 `.tres` 缓存和其他正在运行的预览不被回写。正式关卡、JSON 谱面、关卡编辑器与写谱器的默认规则查询接入同一读取器。

修改 `tuning_stick_deadzone` 只影响物理摇杆到控制向量的转换；默认 0.2 保持现有响应。输入方向和领域时序不变，不降低采样频率。规则字段仍进入既有 `ChartCompiler.rules_hash`；新增死区字段会改变老版本的规则摘要，不能宣称与旧摘要相同。没有新增 Replay 文件格式或录制系统。

JSON 配置元数据已加入导出包含列表。工作簿作为策划侧文件独立放在 EXE 旁，不自动覆盖发布默认规则；如果要把最终平衡固化为发行基线，需要再将确认数值写回原资源并重新构建。日常调参只改这份表即可。

随从技能文案遵守原文约定，不随表格自动改写。若数值改成与原文不同，例如女土蝠变为 5%，菜单仍显示已确认的旧技能描述；提交发行前应由策划确认新原文，而不是程序自行措辞。

## 调参验证

运行 `tests/unit/domain/run_planning_parameters_tests.gd` 检查实际工作簿、基线、字段隔离和输入响应。真实关卡与内嵌预览检查使用对应装配测试。表格首页公式已验证：伤害 20→10 时，可耗尽魂火的伤害组数 5→10，之后恢复原值。

2026-09-14 验证：默认表与临时将 Perfect 改为 50 ms 的表各通过 59 项检查；真实 50 ms 延后输入分别判 Good／Perfect，原资源仍为 45 ms。`tests/editor/run_preview_frame_tests.gd` 的 14 项暂停、跨帧定位、后台休眠及预览恢复检查通过。交付表已保留原默认值，临时副本只在忽略的 `builds/planning/` 中。

本轮新增三类音符独立伤害与空按伤害；旧共用伤害当前值迁移给 Tap 和空按，Hold／Ghost 使用新的默认值。规则摘要随新增字段改变，旧规则 Replay 不应当作相同平衡版本。第三方表格软件的保存格式兼容由 ZIP/XML 样例检查覆盖，尚未通过真人 Excel/WPS 操作完整试玩验收。
