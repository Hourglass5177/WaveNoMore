每关配置对象为 `reward:<stage_id>`，字段如下：

- `next_stage_id`：已登记关卡 ID，留空表示没有下一关。通关后解锁该关并在结算提供入口；失败不显示。建议一次只改一个指向，正常流程不要形成回环。
- `fc_grants_base_pet`：0／1，默认 1。玄同后授予配置随从基础形态。
- `ap_grants_advanced_pet`：0／1，默认 1。至臻后授予进阶形态，同时保证已收服。

奖励对象本身仍在关卡奖励 Resource 的 `pet` 槽选择；本轮未给 Excel 增加重复的资源绑定表。入口分别为 `content/stages/tutorial2/reward.tres`、`content/stages/s07/reward_definition.tres`、`content/stages/s08/reward_definition.tres`。其他测试关保留原配置。临时试玩不发放奖励；本地谱面沿用自身奖励配置，不被正式三关表项覆盖。

结算读取当前存档，显示“女土蝠未收服／已收服／已进阶”等；普通重复通关不会降低已获得状态。基础与进阶描述继续来自随从 Resource，判定等级文案统一为“臻、良、过、失”。

命中率 =（臻＋良＋过）÷ 已结算判定总数；臻率 = 臻 ÷ 已结算判定总数。无记录显示 —；失败仅统计已结算部分。比例不是新的计分规则，也不替代玄同与至臻条件；100% 命中率不保证玄同，因为乱按断连仍参与原判定。

同步工具 `tools/planning/sync_workbook.mjs` 按配置对象／字段保留当前值。目录生成工具也保留奖励表项，后续调整不重置整张策划表。
