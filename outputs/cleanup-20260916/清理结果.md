## 回收站容量事故

执行前漏查了 E 盘回收站上限。原上限 12,582 MB（约 12.3 GiB），Windows 接收后续回收项时淘汰了前部项目。尽管调用的是回收接口，并拒绝直接永久删除，回收站自身的容量淘汰仍发生。这是本次执行失误。

83 个项目、71,848 个文件、约 18.06 GiB 已无法在回收站找到，不能承诺恢复。范围为 `Game/build` 的旧动画采样、临时检查材料，以及 `AudioLab/runtime`、`AudioLab/cache` 的实验运行依赖；不包含正式源码、美术、用户工程、策划表或交付 ZIP。详见 `missing-recycle-receipts.json`。

发现后停止并向用户说明，经用户允许，将 E 盘回收站上限提高到 102,400 MB（100 GiB），保留该设置。续跑逐项检查新回收记录和已有记录，最终仍缺失上述 83 项，没有新增淘汰。

另一个审看目录被 Shell 拒绝整目录回收（0x80270021），已拆分子项完成；未改文件权限。一个元数据短暂占用中断经共享读取修正后继续，已用回收记录补齐执行日志，没有重复删除。

## 恢复与记录

能在回收站找到的项目：打开 Windows 回收站，按原位置查找后选择“还原”。需要批量定位时参考 `recycle-receipts.json` 中的 original、metadata、payload；不要手工删除或重命名 `$I`／`$R` 文件。

- `manifest.json`：最终绝对路径、文件数、体积及理由。
- `recycle-results.jsonl`：每次尝试及续跑结果；包含中途失败记录，最终状态以 `verification.json` 为准。
- `verification.json`：保留文件及回收记录核验。
- `protected-before.json`：7,948 个保留文件的清理前摘要。
- `document-edits.json`、`document-backups/`：计划内说明改动及原文备份。
- `git-before.txt`、`git-after.txt`、`git-cleanup-delta.txt`：Git 状态与本轮差异。
- `recycle-capacity-before.json`：扩容前设置。不要在仍需恢复文件时调低容量。

本次回收 API 的强制回收标记见 [Microsoft IFileOperation 文档](https://learn.microsoft.com/zh-cn/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifileoperation-setoperationflags)；它不能替代回收站容量检查。
