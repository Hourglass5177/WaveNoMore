结论：动画导入、背景遮挡仍未形成完整可用流程，且新增了画布变换、拾取和明确删除按钮的回归。建议先修下面的功能问题，再整理布局，不能把这些提交作为已完成验收的编辑器版本。

依据为本轮用户提供的截图、此前确认的关卡编辑规则、实际源码和 Godot 4.7.2 运行结果；使用 Godot 代码审查及游戏 UI/UX skills。截图中的“没有放在要求的位置”没有明确目标位置，用户授权按专业判断给出建议。

## 必须修复

### 1. P1：背景遮挡把普通对象插进仅接受子层的容器，环境采样报错

位置：`src/presentation/parallax/parallax_controller.gd:37–46`；下游 `:420`、`:328–330`。

新增 `set_object_occlusion()` 将演出对象的普通 `Node2D` 直接放入 `DepthLayer`，但 `_get_sublayer()`、`get_sublayer_velocity()` 仍把每个孩子当作 `SubLayer`。选择“背景后”会把对象移到第一个孩子，随后同深度查询立即遇到类型错误。

复现：加载 `tests/fixtures/environment/a.tres` 创建正式环境安排，把一个对象设为深度 1 的“背景后”，调用正式 `sample_environment(1000000)`。实际先报 `Trying to assign value of type 'Node2D'`，随后背景重挂载拿到空父节点，再报 `Cannot call method 'move_child' on a null value`。这会中断该次环境采样，影响之前已完成的循环换景功能。不是只有编辑器中的显示字段不正确。

建议：使用与现有子层结构兼容的前后对象宿主，并明确它们的所有权和释放路径；背景查询不能把外部演出对象当成子层。修复后覆盖普通背景、动态换景、正负深度、删除和重装关卡。

### 2. P1：画布变换丢失原有基础编辑和自动关键帧语义

位置：`src/tools/level_studio/level_workspace.gd:737–755`、`:239`；候选预览仍在 `:431–451` 使用旧规则。

此次删除了自动关键帧关闭时写入基础属性的分支，并要求当前游标已有完全对应的关键帧，才能提交任何移动、旋转或缩放。开关回调却始终把 `surface.record_at_cursor` 设为 `true`。

通过 Viewport 输入路由实际发送按下、55 逻辑像素移动和松开：

| 场景 | 拖动中的位置 | 松手后的结果 |
|---|---|---|
| 新建文字，自动关键帧关闭 | `(1200,540)` | 回到 `(960,540)`，轨道数仍为 0 |
| 新建文字，自动关键帧开启 | `(1200,540)` | 回到 `(960,540)`，轨道数仍为 0 |
| 已有当前时刻位置键，自动关键帧关闭 | 一直停在 `(960,540)` | 松手突然跳到 `(1200,540)` |

前两种操作弹出“当前游标没有对应关键帧”的拒绝提示；第三种候选和提交写入了不同位置，无法边拖边看。数值面板仍遵循关闭改基础、开启写动画值的规则，形成同一属性两套操作逻辑。新增指南第 69–71 行要求只改已有键，而第 84 行仍说明自动关键帧的原行为。

建议：恢复此前已确认的基础值／自动关键帧规则，让画布、字段、候选预览和提交走一致目标。若另需“只改已有键”的模式，应单独定义，不应使自动关键帧开关失效。覆盖新建对象、已有键、无当前键、多选、撤销和取消。

### 3. P1：简化动画导入没有接通正常文件路径，也没有完整携带依赖

位置：`src/content/level_format/level_asset_library.gd:30–46`，新增动画分类 `src/tools/level_studio/level_workspace.gd:370–378`。导入入口仍为 `:928–934`。

“导入素材”窗口仍仅允许图片、声音和字体。即使直接调用导入，把 `monkey.tres` 放进项目 `assets/`，相对路径解析也没有 `.tres/.res` 分支。新增的项目根目录回退把 `path` 改成 `res://...`，后面却检查原始 `asset` 的前缀，因此这个回退也不能加载序列帧。

实际结果：`resolve("assets/monkey.tres")` 和回退路径均返回空；直接完整的 `res://assets/image/animation/monkey/monkey.tres` 能取得 16 帧。相对资源会落入“字体”分类，拖入后创建普通空精灵，无法显示动画。

另外，原 `LevelProjectIO.import_file()` 只复制单文件，`dependencies()` 只枚举直接引用；新动画类型没有补充依赖处理。复现导入后收集到 `[level.json, show.json, song/song.json, assets/monkey.tres]`，其中没有任何序列帧图片。仅补加载后仍不能保证交付关卡能显示动画。

建议：明确序列帧／动画场景的制作端输入，接通入口、分类、解析、纹理依赖复制和包内重定位；同时检查另存、恢复和 ZIP。现有 PCK 流程可以继续保留，不能把开发机的 `res://` 路径当作独立关卡的可携带资源。

### 4. P2：已成功加载的动画也不会按新对象默认行为播放

位置：`src/runtime/director/level_show_player.gd:54–59`；交互问题还涉及 `level_workspace.gd:774–781`。现有驱动行为在 `level_animation_driver.gd:31`、`:62–76`。

新代码调用 `AnimatedSprite2D.play()`，随后 `LevelAnimationDriver.configure()` 立即禁用处理并暂停它。没有动作片段时，驱动永远用 `default` 和局部时间 0 采样。实际 `monkey` 在歌曲 450 ms 时仍为第 0 帧；手动提供正确的 `default` 动作片段后为第 5 帧，说明贴图本身能显示。

“添加动作片段”也未接入新增的 `animation_names()`：`assets.actions()` 只读取素材包的 `state_names`，普通 SpriteFrames 返回空，默认创建 `idle`，而示例序列只有 `default`。因此用户点击新快捷按钮也不能自然补全播放流程。

建议：简单动画明确使用可定位的默认动作时间；如果产品要求必须有片段，则导入时提供创建入口并选到素材中存在的动作。动画名、循环和偏移都要被统一采样，不以实际播放帧数累计。

### 5. P2：清除动画引用会触发播放器空资源错误

位置：`src/tools/level_studio/level_workspace.gd:689–700` 与 `src/runtime/director/level_show_player.gd:54–59`。

“删除资源引用”保留 `animated_sprite` 类型并清空 `asset`、`animation`。重建后仍调用空帧资源的 `play()` 和驱动。复现数据与按钮生成的数据一致，日志出现两次动画名称为空错误，继而在 `LevelAnimationDriver.sample()` 报 `Cannot call method 'has_animation' on a null value`。后续采样也会再次走这个路径。

建议：清引用后显示可重新绑定的空对象；没有资源时不建立动画驱动。补一次按钮清除、恢复绑定及撤销的完整流程。

### 6. P2：遮挡改回“不参与”或 HUD 后，对象仍留在背景 CanvasLayer

位置：`src/runtime/director/level_show_player.gd:121–124`。

新逻辑只处理进入遮挡，没有处理退出。将对象设为背景前／后再改成“不参与”，调用正式 `seek()` 后，`wrapper.get_parent()==player` 仍为 `false`。改成 HUD 也只是跳过本次挂载，并未还原父节点。字段已更新、画面层级却仍受旧 CanvasLayer 控制；只有某些触发整场景重建的操作才会恢复，不能依赖这种偶然刷新。

建议：每次遮挡状态变化都能对称地迁入／迁出正确宿主，并保留显示变换；撤销、坐标层修改及父组继承变化也要走这条路径。

### 7. P2：“背景前／后”只调整兄弟顺序，仍被对象 z_index 覆盖

位置：`src/presentation/parallax/parallax_controller.gd:45–46`；对象层级写入在 `src/runtime/director/level_show_player.gd:121`。

GPU 复现：蓝色背景深度 4，红色对象“层级 4、背景遮挡深度 4、背景后”。对象已经排在第一个孩子，但 `z_index=4` 仍让它盖在背景上。截图中心像素实际为红色 `(1,0,0,1)`，预期应为蓝色。

建议：背景前后顺序和对象之间的局部排序需要分开表达。不能只调用 `move_child()` 就认为覆盖了 Godot 的 z_index 和 CanvasLayer 排序。

### 8. P2：新增拾取排序与实际画面不一致，连原有 HUD 也受影响

位置：`src/runtime/director/level_show_player.gd:162–165`、`src/tools/level_studio/level_preview_surface.gd:153–155`。

新 `object_render_order()` 忽略 HUD 的实际 `z_index=1000`，也未表达前景／背景 CanvasLayer 的顺序；背景深度方向与普通对象 z_index 的方向并不相同，不能统一成 `depth*2`。

复现：绿色 HUD 和层级 5 的红色世界对象重叠，GPU 中心像素为绿色，说明 HUD 在上；同一位置发送鼠标按下后，却选中了下面的世界对象。这个例子没有启用新遮挡字段，旧工程同样会受到回归影响。

建议：让拾取共用实际显示顺序，至少覆盖 HUD、普通世界对象、背景前后插入对象和同层多对象。用可见像素与选中结果配对验证。

### 9. P2：明确写着“删除对象”的按钮仍由时间线目标分流，可能无效

位置：`src/tools/level_studio/level_inspector.gd:28`，调用 `level_workspace.gd:795–796`。

实际流程：新建对象并插入位置键 → 选中该轨道标题（未选关键帧）→ 右侧出现对象属性和“删除对象” → 点击按钮。此时 `edit_target=timeline`，回调转而删除空的时间线选区，对象保留。

建议：明确命名的对象按钮绑定对象删除命令，并保留原对象及相关轨道的一次撤销；通用 Delete 快捷键才按当前编辑目标分流。删除按钮确实已经存在，截图中“没有找到”主要是入口显隐和操作语义问题。

## 布局与可发现性建议

新六按钮使用 `HFlowContainer`，能够换行，未发现因此产生固定坐标越界。问题是功能分组与上下文：时间编辑按钮挤在画布操作中，“对齐中心”与移动工具被换行分开；适应画面、定位选中又排在片段按钮后面。1280×720 和 1920×1080 自动倍率下均观察到两行；实际最大化也保持两行。

建议按以下位置整理，无需另建通用 UI 框架：

| 区域 | 功能与顺序 |
|---|---|
| 画布工具栏 | 移动、旋转、缩放；对齐；适应画面、定位选中；网格、路径 |
| 时间线编辑区 | 插入关键帧（可选属性）；游标拆分；添加片段（动作、显示、音频） |
| 素材／对象区 | 导入素材、导入包、添加对象；保留对象树底部的复制、分组、删除 |
| 对象属性 | 素材选择旁放“清除引用”；空引用时禁用。背景层按名称和深度供选择，前后关系紧邻它显示 |

无适用对象或片段时，快捷按钮应禁用并给出原因，避免等点击后才知道没有操作目标。保留菜单作为完整入口和快捷键提示，不必把菜单每个条目全部平铺到画布顶部。删除资源引用目前对文字等无素材对象也一直展示，容易让人误解为删除素材文件，可改为明确的“清除引用”。

“层级”“背景遮挡深度”“背景遮挡”三个字段缺少关系说明。建议将“插入哪一背景层、前还是后”组成一组，把对象局部排序／镜头视差的参数单独标识，避免美术认为两个深度字段必须填同一个数字。
