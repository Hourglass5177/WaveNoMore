### 2026-09-09 复发后的根因与修复

上述刷新补丁没有找到根因。此次用户确认五轨标题仍在、重新打开恢复、使用手柄；已复现一致现象：手柄操作同时进入后台写谱器，误触“当前位置设为首拍”，改变全谱音频位置。波形与轨道标题仍正常，当前时间范围却没有音符。不是独立试玩进程清空了音符数组。

- 保全现场 JSON、工作区、恢复备份和日志后，以 `test` 只读装入运行验证。两个难度及备份均为 38 个 Tap/Hold、6 条 Tuning、7 批 Ghost。
- 在真实配套游戏握手 `ready` 后，向后台写谱器递送摇杆 GUI 事件。由试玩按钮出发，经右、下、下、左、左移到首拍按钮，再按手柄确认：首拍从 **919.8 ms 改为 45560.1567 ms**，当前可见对象从 **10 变为 0**；内存对象总数一直为 **51**。这是一条可重复触发的路径，并非从旧日志还原了用户当时的每次按键。
- Godot 默认允许后台应用收到手柄事件，参见[官方说明](https://docs.godotengine.org/en/stable/tutorials/inputs/controllers_gamepads_joysticks.html#window-focus)。写谱器启动时启用 `Input.ignore_joypad_on_unfocused_application`，在输入源处隔离后台手柄；专用试玩期间主工作区还会消费摇杆和按钮事件，覆盖焦点交接及已排队事件。切回写谱器仍可用鼠标、键盘继续编辑。
- 删除退出试玩时无依据的全量索引重建；不通过重新打开工程覆盖错误，更不会覆盖试玩期间的正常修改。未改游戏输入、判定、手柄映射或谱面协议。
- 新增 `run_background_input_tests.gd`，通过 `Input.parse_input_event` 进入真实 GUI。修复前首拍、可见数量、焦点和撤销检查失败；修复后全部通过。该测试加入常规写谱器测试入口。
- `run_trial_document_tests.gd` 改为真实子进程配合手柄事件，移除人为清空索引的旧测试。用户谱面测试前后序列化、索引、未保存标记和撤销游标保持一致。`run_ui_tests.gd` 通过。
- 合成 GUI 事件验证了控件隔离；后台原生输入开关已确认本机 Godot 4.7.2 支持。未把自动注入测试宣称为人工拿手柄完成整曲验收。

复现日志与现场副本位于本机 `builds/trial-disappearance-0909/`。用户原谱不需迁移；旧版本误触后尚未保存时，重新打开原 `song.json` 可恢复已保存的对齐；也可撤销首拍修改。
