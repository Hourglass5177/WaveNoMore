# 冥河写谱器使用说明

当前开发版支持 Tap、Hold、Tuning、Ghost 五轨编排及 BOSS 来源标记。新机制操作与预览限制见 [Tuning / Ghost 编排](chart-editor-tuning.md)，完整验收进度见 [开发记录](chart-editor-progress.md)。

单条 Tuning 的属性支持“自动半径”和自定义“半径（px）”，可分别安排生、死两侧的轨道位置。半径按 1920×1080 设计画布计算，只影响布局；节点角度、时间和调频要求保持不变。

## 真人试玩与导入游戏

顶部“在游戏中试玩”会使用当前难度的未保存版本，启动配套 `game/minghe.exe`，三秒准备后从音乐开头真人试玩。写谱器保留原位置并暂停；关闭试玩窗口后才能再启动。游戏的“选关 → 本地谱面”支持导入 ZIP、选择难度、重试和独立成绩。详见 [导入与试玩说明](local-chart-playtest.md)。

试玩时切到游戏，后台写谱器会暂停预览绘制以减少占用；切回后恢复原位置，可以继续编辑。

导出谱面也不再替你保存工程；请按 Ctrl+S 明确保存项目。

## 开始一张谱

1. 运行 `minghe-chart-studio.exe`，不需要安装 Godot。点击“导入音乐”，首次使用时先选择一个项目目录，再选择 WAV、Ogg Vorbis 或 MP3。
2. 在左侧填写歌曲、作者，在右侧设置 BPM；使用时间线旁固定的“音乐对齐”区设置首拍。点击时间尺定位，结合波形和节拍器检查对齐。
3. 下方前两轨分别是生钟、死钟的 Tap/Hold；后面是生／死 Tuning 和 Ghost。空白点击画 Tap，沿时间拖动画 Hold；反向拖画也有效。超过 6 像素才成立为拖画。
4. 空格试听／暂停。上方会自动演示正式关卡表现；定位到 Hold 中段会恢复持续状态。大谱定位时显示“正在定位…”，可再次定位取消旧请求。
5. Ctrl+S 保存，重新打开项目里的 `song.json`。交付时点“导出谱面”，选择需要交付的难度。

音符横向位置表示要求起手的时刻。背景里的生成、接近和波传播由游戏规则计算。

## 音乐与首拍对齐

“音乐对齐”位于播放栏下方，选中音符时仍可使用。首拍偏移是**有效 tick 0 在音频中的位置**，正数表示首拍在音乐开始之后，负数表示在音乐开始之前。全谱偏移非零时，下面额外显示谱面 tick 0 的实际音频位置。

| 操作 | 方法与效果 |
|---|---|
| 选点设首拍 | 先定位播放头，再点“当前位置设为首拍”；也可在波形上右键选择“将此处设为首拍” |
| 拖首拍 | 拖动金色首拍把手，波形位置固定，节拍网格和音符随首拍移动 |
| 移动波形 | 开启“移动波形”，按钮和波形区高亮；左右拖动波形，网格和音符保持屏幕位置。波形向右拖，首拍偏移减小 |
| 精确输入 | 输入有符号毫秒数，Enter 或离焦提交；±1.0 和 ±0.1 按钮分别微调 1 ms、0.1 ms。没有 ±30 秒限制，不主动降低已有数值精度 |
| 找回首拍 | 点击“定位首拍”，播放头和视口移到首拍；支持负时间 |
| 多难度一致 | 默认只改当前难度；“同步至全部难度”复制当前首拍偏移，保留各难度 BPM 和全谱 tick 偏移，可一步撤销恢复各自原值 |

对齐不吸附到节拍网格，拖动中按 Shift 将移动量降至十分之一。一次拖动只提交一次撤销；Esc 或窗口失焦取消候选并恢复视口。开始调整会暂停试听并保留音频位置，完成或取消后由你继续播放。关闭“移动波形”后，拖动普通波形区域恢复为定位播放头，金色把手仍用于调整首拍。

首拍对齐只改变音乐与谱面的时间关系，不改 Tap 的 tick、Hold 长度、BPM、全谱 tick 偏移或音频文件。偏移随当前项目保存、恢复及谱面包导出；可配合节拍器、循环和变速反复试听。拖动期间更新候选网格，松手后才刷新内嵌正式预览。

## 播放控制栏

三角图标播放，播放时切换为暂停图标。左箭头加竖线返回音乐开头；循环箭头高亮表示循环已开启。悬停可查看按钮含义和快捷键，循环起止按钮还会显示当前范围时间。

“倍速”选择试听速度；“吸附”选择音符细分或关闭吸附。窗口缩小时工具栏按组换行，左右侧栏可滚动，专业字段仍直接显示。难度标识用于文件名；起始位置、时长和全谱偏移保留 tick 单位。

## 常用操作

| 操作 | 方法 |
|---|---|
| 选择、移动 | 点击音符选中；拖动已选成员移动选区 |
| 多选 | Shift 点击增减；Shift 在空白拖动框选 |
| Hold 头尾 | 拖头固定尾，拖尾固定头 |
| 自由拖动 | Alt 临时关闭吸附 |
| 平移、缩放 | 滚轮／双指纵滑上下浏览轨道；双指横滑／中键拖动左右浏览；Ctrl+上下滚轮围绕鼠标缩放 |
| 取消手势 | Esc；窗口失焦也取消尚未提交的手势 |
| 复制／粘贴／剪切 | Ctrl+C／V／X，粘贴锚定游标，完整双押重新生成组标识 |
| 重复、生死互换 | Ctrl+D、Ctrl+M；也可用右键菜单 |
| 删除 | Delete，不推移后续音符 |
| 量化 | Q 量化起始位置并保留时长；Shift+Q 量化起止位置 |
| 撤销／重做 | Ctrl+Z、Ctrl+Shift+Z 或 Ctrl+Y |
| 步进输入 | 暂停时按 F／J 输入生／死；按住并移动游标可输入 Hold |
| 移动游标 | 左右方向键按吸附步长移动；PageUp／PageDown 按当前小节长度移动 |
| 循环 | “循环起点”（I）和“循环终点”（O）设置范围；循环箭头按钮或 L 开关循环 |

编辑器 F／J 对应时间线的生／死顺序。游戏自己的物理键位由游戏侧维护。文字框获得焦点时，空格、F、J 用于输入文字。属性输入可按 Enter，离焦也会提交；保存前会提交正在输入的属性。

右侧支持批量音符属性、分组、时间变化、段落名称和配色；场景选择固定在预览区上方。复制难度后可在右侧修改难度标识。试听倍率为 0.5、0.75、1、1.25、1.5。

## 场景与美术更新

新建项目或新增空白难度时，默认选择场景列表的最后一项，目前为 s08；演出默认关闭。打开已有谱面或复制难度时保留原来的场景配置。

预览上方的“场景”读取游戏的关卡目录，包含 s08 等已接入场景；选中音符时也能切换。选择后，当前歌曲和谱面使用该关卡的背景、视差、角色、编钟及音符素材。场景按难度保存，支持撤销重做、复制难度和恢复稿，配色覆盖在切换时保留。

“使用场景演出”默认关闭。开启后，原场景的文字和定时演出按当前谱面的 tick 与 BPM 播放，拍点不会自动适配另一首歌，也不会延长谱面。旧谱显示“旧版主题”，保留原表现，明确选择场景后才改用完整场景。

美术在 Godot 工程中保存修改并等待素材导入完成后，点击工程内写谱器的“刷新场景”，即可重新读取场景列表和当前场景素材。切换或刷新会暂停试听，保留当前位置；完成后按空格继续。资源缺失时会显示在问题列表，草稿仍可保存。

发布版使用构建时内置的场景，没有工程刷新按钮。新增或修改游戏美术后，需要同步重建写谱器与配套游戏，再交给谱师。谱面 ZIP 只保存场景引用、谱面和音频。开发接入步骤见 [场景接入说明](chart-studio-scenes.md)。

“音符提示音”在 Tap／Hold 起手时敲钟；“节拍器”按拍号打拍，小节第一拍加重；“游戏反馈”单独控制持续音与判定音。对齐时可先只听音乐与音符提示音，避免把声波接触时的判定反馈误认为起手时刻。三种声音独立控制，编钟音色保持不变。

提示声音提前约 100 ms 排入音频队列。播放中修改只影响尚未交给音频设备的部分，不补播历史提示，也不重新播放整首音乐；定位、切换倍率与循环会重建同步起点。若主线程严重卡顿导致缓冲不足，状态栏会提示已重新同步。

## 保存、恢复和旧谱

项目包括 `song.json`、`charts/`、`audio/` 和本机视图状态 `editor/workspace.json`。移动项目时一起移动整个目录。音频失去关联时用“导入音乐”重新指定文件。

未完成或有玩法冲突的草稿可以保存。“问题（数量）”可展开或收起列表，点击问题可定位对应时间；新问题自动展开，问题修正后自动收起；不可解释的音符不会悄悄进入旧预览。正式 ZIP 导出会检查所选难度，并排除工作区状态、缓存和迁移归档。

修改提交后等待 1 秒生成恢复稿，连续修改会合并；录制结束立即更新。恢复提示显示保存时间、歌曲及各难度音符数，恢复后重新生成波形并回到原难度和视图。异常退出后再启动可恢复；正常退出提供保存、放弃、取消。上一版文件另有 `.bak` 备份。

导入旧 `.tres` 时选择旧关卡入口和新的目标目录。只转换 Tap/Hold 和可表达的数据，原文件与依赖保存在 `legacy/`，差异见 `legacy/import-report.json`。旧关卡只有程序占位音频时，需要另外导入歌曲。另存为会复制迁移归档。

设备试听补偿属于本机工具设置，和歌曲首拍偏移分开。保音高质量、同步与密集谱面性能的实测限制请看开发记录，暂不把本开发版当作已完成正式验收的发布版。


## 实时录入与时间线

先点击“录制”（R），再播放音乐。F 输入生钟、J 输入死钟；短按不超过 150 ms 为 Tap，较长按住为 Hold。可在右侧“试听”的“长按判定（ms）”调整阈值，按真实按住时间计算，慢速播放也不改变短按手感。音符起止跟随当前吸附；关闭吸附则按 tick 记录。

松开的音符立即显示在时间线上；本轮播放仍演示录制前的谱面。暂停、关闭录制或音乐结束，才一次性提交本段，可用一次撤销移除。失焦、打开对话框、主动定位或更换吸附时结束当前段，丢弃尚未松开的键，保留已完成音符。循环回绕截断 Hold，须松键后才能再次录入。循环边界不足一格时尾段会短于吸附步长；吸附后没有可用时长则保留为 Tap，不跨到下一轮。文字输入时 F/J 不录音符。

时间线上方是秒标尺，音乐零点有贯穿轨道的零刻线；负时间区有底色，首拍单独标注。拖动标尺或默认模式下的波形定位，拖动循环起止把手调整范围。滚轮和双指纵滑上下浏览轨道；双指横滑、中键拖动、底部滚动条左右浏览时间；拖动音符到两侧边缘会自动滚动。手动横向浏览暂时解除播放跟随，重新播放或点击“跟随”恢复。

触摸板横向双指滑动保留细小滚动量，方向跟随系统。斜滑的两个分量分别移动时间和轨道，不再把纵向分量折算成横移。上下浏览不解除水平方向的播放跟随。浏览不改变播放位置或谱面；正在拖画音符、拖动选区或调整首拍时，滚动不会改变当前手势基准。

“视图”菜单提供自动界面缩放、100%／125%／150%，以及显示整曲、显示选区。自动缩放随窗口增大同步放大按钮与文字。

拖动配色时即时预览，关闭颜色弹窗提交一次修改；一次撤销恢复弹窗打开前的颜色，不打断音乐。


## 调整工作区大小与预览清晰度

拖动预览与播放栏之间的横向分隔条，可以把时间线压缩，扩大预览；两侧竖向分隔条可调整歌曲栏和属性栏宽度。五轨行高可从视图菜单调整，紧凑分区通过轨道滚动条访问下方内容，不会固定挤占预览。

“视图”菜单可以分别隐藏歌曲侧栏、属性侧栏和时间线。“专注预览”暂时隐藏这三块区域，保留播放控制；再次点击恢复原布局。调整乱了可选择“恢复默认布局”。分区位置和显示状态随项目工作区及恢复稿保存。

工具文字使用窗口原生渲染，按钮图标支持高倍率显示；预览最低以 1920×1080 渲染，显示区域超过该分辨率时继续增加渲染像素。拖动分隔条不重新装入谱面、不改变游戏坐标，也不打断音乐。预览保持 16:9，因此区域过宽或过高时仍会留边。

## 自动分析、修正与 Tap 草稿

请完整解压开发包，保留主程序旁的 `rhythm_analyzer` 文件夹及其中的模型。识别在本机完成，无需安装 Python。导入音乐后，在“音乐对齐”中打开“分析节奏／生成草稿”。分析窗口可以移动、调整大小，操作时间线时可以将它移到一旁。

1. 选择“全曲”或“循环选区”，点击“分析节奏”。界面显示解码、加载模型、识别拍点、拟合阶段；可取消。“重新分析”忽略已有缓存。完成前谱面保持原样。
2. 试听并确认结果。蓝色短线是检测拍点，紫色是检测到的小节第一拍，绿色是修正网格。橙色底纹和问题列表标出可能变速、缺少拍点或小节位置不一致的区域；点击问题定位。拟合偏差不等于识别准确率。
3. 输入 BPM，或用 `÷2`、`×2`、`原始建议` 调整。选择 3/4 或 4/4；“拍号需确认”表示模型没有给出稳定结论。拖动绿色标记整体对齐，右键候选拍可设为小节第一拍，也可以使用游标定位、±1 ms、±1 拍。两拍校准需要先在主时间线记录 A、B，再填入两点间的拍数。
4. 开启“试听候选节拍”，用空格或主播放按钮试听；高音表示小节第一拍。输入框内的空格仍用于文字输入。此时游戏预览仍使用正式谱面。确认后点击“应用到当前难度”：替换该难度的 BPM、拍号和偏移，保持已有音符 tick、Hold 长度及组合，可一步撤销。其他难度不变。
5. 选择“每小节第一拍”或“每拍一个”，选择生钟、死钟或生死交替，点击“预览 Tap 草稿”。范围使用全曲有效制谱区间或循环选区；全曲与谱面结束位置取交集。可用循环选区排除不可靠段落，不会自动省略可疑区域。
6. 检查待生成数量、重复及冲突，点击“确认生成”。重复 Tap 和正式规则冲突会跳过，已有音符不移动、不删除。整批生成可一次撤销。之后修改分析候选不会自动改变已生成音符。

已有手动时间映射也可以直接生成草稿，不必运行识别。若当前有尚未应用的候选，先应用或“取消候选”。草稿按正式拍号和节拍生成，不受当前 1/16 等吸附选项影响。

“初始 BPM”修改初始速度；“在当前位置添加变速”用于手动变速谱。自动分析目前只提供固定 BPM 候选，不自动制作变速表。缓存位于工具用户目录，不进入歌曲 JSON 或游戏交付 ZIP。

建议 BPM 来自局部稳定段；参考小节单独选取，修改 BPM 会保持该参考拍的音频位置。可先用循环选中节奏明确的一段，再点“用循环选区重新拟合”，不必重新运行模型。界面同时显示建议、候选及已应用 BPM，并按段显示正负偏差、漂移趋势和检测覆盖。正偏差表示网格比检测点晚；检测点本身不是人工真值。半速／倍速、前后段相位不同的歌曲仍需试听判断，不能仅凭“全曲平均误差更小”认定更准。

如果只是敲钟听起来晚，先核对提示音同步，再决定是否修改歌曲首拍。设备补偿只影响本机，歌曲首拍和 BPM 则会改变所有玩家听到的对齐关系。开发记录附有 test 歌曲的只读比较，未自动改写其谱面。

开发者重新构建完整开发包，可从 Game 运行 `tools/rhythm_analyzer/build.ps1 -PythonExe <Python3.12路径> -GodotExe <Godot4.7.2路径> -InstallDependencies`。首次安装需要联网；以后可省略 `-InstallDependencies` 复用独立构建环境。脚本默认只导出写谱器；加 `-WithGame` 同时制作配套游戏，输出 `builds/minghe-chart-studio-dev.zip`。测试范围和未验收项见 `docs/chart-editor-rhythm-analysis.md`。

问题区域仅在存在问题时显示，默认展开紧凑列表；可以收起，点击具体问题定位。问题全部修正后入口和列表一同隐藏。

Ghost 会从画面内有足够间距的真实交点中随机抽取指定数量；相同谱面与演奏可重复定位。命中时仍凑不足时，属性显示实际数量与“交点不足”，不会复制同一点凑数。完整理想调频预测和独立计分仍待后续接入。

轨道默认折叠为 24 像素的紧凑行，可直接点击放置 Tap/Ghost、拖画 Hold/Tuning，以及选择和修改已有音符。点击左侧轨道标题展开或折叠；“视图”菜单可全部折叠／展开。首次升级旧工作区采用紧凑布局，此后记住各轨道的展开选择。紧凑行的金色 B 小徽标表示 BOSS 来源，悬停可查看。

波形带为 24 像素，连同秒尺、节拍辅助尺和注释行共 72 像素。首拍标记保留拖动，详细时间可悬停查看；BPM 与段落共用注释行。Ghost 使用独立灰白色系轨道底色，与生死两侧区分。

角度圆盘的两个卡槽是生死分界，拖动和数值输入均不能越过本侧半圆。已有越界路径会标出对应节点，修正后恢复预览。定位期间保留上一张完整画面，完成后切换到目标位置，不显示历史重演中的动画。等待超过 200 毫秒时，预览区出现半透明黑色蒙版、“正在加载和定位”和转动提示；快速定位不显示蒙版。等待期间仍可在时间线上重新定位，最新位置生效。
