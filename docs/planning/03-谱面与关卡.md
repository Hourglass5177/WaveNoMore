# 谱面、关卡与布局参数

这些字段具有逐首歌、逐难度或逐对象的含义，继续在现有写谱器／关卡编辑器调整；不把每个音符复制到全局 Excel。下面列出策划相关字段，省略资源 ID、材质细节和微小特效时长。

## 1. 歌曲与谱面时间

入口：写谱器的歌曲、难度和音乐对齐；源码 `src/content/chart_format/chart_json_codec.gd`、`src/content/resources/song_chart.gd`、`song_definition.gd`。

| 字段 | 默认／现状 | 单位与数量级 | 调整含义 |
| --- | --- | --- | --- |
| `timing.tempo_events[].bpm` | Resource 新建 120；JSON 需要实际 BPM 事件 | 常见编排可从 60～200 BPM 理解，实际必须服从音乐 | 决定 tick 到时间的换算；不是整体变速试听 |
| `timing.tempo_events[].tick` | 0 | 整数 tick | 变 BPM 生效位置 |
| `timing.first_beat_offset_ms` | 缺失 0；每难度独立 | 1 ms / 0.1 ms 微调；长前奏可到数万 ms | 有效 tick 0 对应的音频位置；正值把首拍放到音频开始之后 |
| `timing.chart_offset_ticks` | 0 | 按所需节奏偏移，通常保持 0 | 全谱 tick 平移；和音乐首拍、设备校准分开 |
| `timing.ppq` | 480 | 每四分音符 480 tick | 固定制谱精度，通常无需调；240=八分、120=十六分、160=八分三连音 |
| `timing.end_tick` | 新资源 0；真实谱需设置结束点 | 按音乐结束位置 | 决定谱面有效长度，不能短于已有事件 |
| `meter_events[].numerator/denominator` | 4/4 | 按音乐拍号 | 影响小节网格，不单独改变 BPM |
| `SongDefinition.preview_start_sec` | 0 | 秒 | 选曲试听开始位置，可取副歌起点 |
| `SongDefinition.preview_duration_sec` | 15 | 常用 10～30 s | 选曲试听片段长度，非游戏倒计时 |

以 BPM=120、PPQ=480 为例，一拍 500 ms，一个 tick 约 1.042 ms。不要通过修改 PPQ 把同一份 tick 数据“加快”；改变精度需同步换算事件。

## 2. Tap、Hold 与组合

入口：写谱器音符属性；资源 `src/content/resources/note_event.gd`。

| 字段 | 新建默认／规则 | 建议理解 |
| --- | --- | --- |
| `kind` | Tap；JSON `tap` / `hold` | 音符机制，不是伤害类型 |
| `affinity` | 生侧；JSON `zhu` / `xuan` | 所属钟与输入侧；两侧使用同样数值规则 |
| `tick` | 0 | 头部节拍位置；优先跟音乐节奏编排 |
| `duration_ticks` | 0；Tap 固定为 0，Hold 需正数 | Hold 可先以半拍、1/2/4 拍试写，依曲段决定；整条只结算一个普通音符单位 |
| `group_id` | 空 | 组合身份；参与双押识别和默认伤害分组。不是额外的毫秒宽限 |
| `damage_group_id` | 空 | 显式伤害分组；为空回退 group_id，再为空回退音符 ID。相同组多个漏击只扣一次 |

没有每个音符独立的伤害、判定窗或分值。音符密度、单双侧切换、双押比例、Hold 重叠长度都是谱师通过事件编排决定，没有一个“整体难度倍率”可以代替编排。

## 3. Tuning 与 Ghost

入口：写谱器 Tuning 属性及节点、Ghost 属性；资源 `tuning_path_event.gd`、`tuning_path_point.gd`、`ghost_event.gd`。

| 字段 | 默认／当前限制 | 数量级与影响 |
| --- | --- | --- |
| Tuning `tick` | 0 | 整条开始 tick |
| `points[].offset_ticks` | 首点 0；后续严格递增 | 决定每程持续时长与折返时刻；短于当前 500 ms 容错的程要重点试玩 |
| `points[].angle_deg` | 新节点 0，但合法范围依侧别与当前规则 | 每段最小跨度 28°；当前频率尺度下最大约 97.63°，并检查累计频率范围；不是自由 360° |
| `hold_id` / `support_hold_id` | 空，正式有效路径必须关联 | 对应同侧及另一侧 Hold；整条 Tuning 必须被两条 Hold 的重合时间窗覆盖 |
| `visual_radius_px` | 0=自动 | 1920×1080 设计坐标；自定义可先试 300～550 px，检查出屏和重叠。只改变显示半径，不改变频率／摇杆判定尺度 |
| Ghost `tick` | 0 | 必须位于关联 Tuning 窗口 |
| Ghost `count` | 1；允许 1～16 | 可从 1～4 个观察画面密度；足量候选与波前几何有关，不是额外扣血数量 |
| Ghost `tuning_ids` | 空，正式编排需关联 | 同时生效的每侧 Tuning 都应关联，最多两条 |

写谱器保存的是节点角度，运行前由 `ChartPathAdapter` 转成滑条频率。不要直接改临时生成的 `start_value/end_value/traversal_ticks` 来覆盖新编排；应修改源 Tuning。最低／最高频率、基频或每 Hz 尺度变化后，路径会按新规则重新适配并校验，某些旧角度跨度可能不再合法。

Ghost 不追加独立计分单位；关联调频失败时，每枚按 `ghost_miss_damage` 扣血。预测交点不足单独报告，不作为玩家失误。旧 `SuManifestationEvent` 的生成区域默认 `Rect2(0.25,0.2,0.5,0.6)`，新写谱器未提供这项全局编辑。

## 4. 关卡、通关与奖励

入口：关卡编辑器属性；`content/stages/<关卡>/stage_definition.tres`、`src/content/level_format/level_format.gd`、`src/content/resources/reward_definition.gd`。

| 字段 | 默认／现状 | 含义与建议 |
| --- | --- | --- |
| `debug_nonlethal` | 类型默认 false；现有 s01～s08 全部 true | 数值压力测试时需显式关闭；不是玩家可获得的技能 |
| `rule_set` / JSON `rule_path` | 共享默认规则 | 无策划表时选择本关规则；有表时列出的字段由表覆盖 |
| `order_index` | 0 | 选关排序，越小越靠前 |
| `unlocked_by_default` | Resource false；JSON 关卡装配缺失时 true | 新存档是否直接开放 |
| `next_stage_id` | 空 | 通关解锁下一关；空表示不串联 |
| `pet` / `pet_path` | 无 | 本关 FC/AP 的目标随从；不是强制装备 |
| `fc_grants_base_pet` | true | FC 授予基础形态 |
| `ap_grants_advanced_pet` | true | AP 授予进阶形态 |
| `intro_us` / `outro_us` | 0 | 片头／片尾，微秒存储；1 s=1,000,000 us；依演出长度配置 |

通关要求未失败、判定单位完成且抵达伤害已处理。FC 看最终 Miss 数与会断连的乱按数；AP 在 FC 基础上要求非空判定全部 Perfect。没有“90% 算 FC”等可调阈值。进阶苹果蛇可提升最终判定但保留失误伤害，结果必须同时看魂火与成绩。

## 5. 读谱布局和演出节奏

以下是现有资源中的策划／关卡美术共用入口，没有加入频繁调平衡的 Excel。所有坐标是 **1920×1080 设计像素**，不是显示器实际像素；切换 2K/4K 不应把这些坐标乘分辨率倍率。

| 入口与字段 | 当前默认值 | 建议尺度与影响 |
| --- | --- | --- |
| GameplayRuleSet `life_wave_origin` / `death_wave_origin` | (350,280) / (1570,800) | 波源；修改需同时核对角色、钟、分界与 Tuning 角域，保持中心对称 |
| `life_note_spawn` / `death_note_spawn` | (2040,220) / (-120,860) | 音符入场点；在画布两侧外约 120 px |
| `life_note_cue` / `death_note_cue` | 都为 (960,540) | 中央判定提示点，通常保持固定 |
| `note_curve_outer_bend_px` | 220 | 路径外弯，必要时以 10～20 px 调整 |
| `note_curve_center_handle_px` | 360 | 中心附近曲率控制，必要时以 10～20 px 调整 |
| StageVisualTheme `camera_velocity` | 类型默认 (0,0)，各场景可覆盖 | 设计 px/s；仅表现移动速度，可先以 20～100 px/s 观察，不能当判定速度 |
| 背景子层 `velocity` | (0,0) | 叠加该子层独立运动，配合场景视差层级 |
| StageSession `resume_countdown_sec` | 1.25 s | 暂停返回准备，可在 1～3 s 试调；场景 Inspector 配置 |
| StageSession `finish_settle_sec` | 0.35 s | 成功收尾最短等待，实际还需物理表现完成 |
| StageSession `pause_on_focus_loss` | true | 失焦暂停，建议保持 |

整体相纹亮度已有玩家设置：默认 85%，范围 35%～100%。音乐/玩法音效/UI 默认 -4/-2/-4 dB；输入、音频、视觉校准均默认 0 ms，属于每台设备／每个玩家的设置，不通过全局平衡表覆盖。细碎 shader 参数、白光淡入、碎片生命周期和固定视觉语言本表不展开。
