# Tuning、Ghost 与 BOSS 编排

2026-09-08，写谱器增量规格与当前实现。原有 Tap/Hold、录制、节奏分析、时间映射和音频流程继续使用。

## 五轨工作区

轨道从上到下为：生钟 Tap/Hold、死钟 Tap/Hold、生钟 Tuning、死钟 Tuning、Ghost。默认五轨均折叠为 24 像素高的紧凑行，音符仍可见、可选择、可点击放置和拖画；折叠不再隐藏音符或禁止编辑。点击轨道标题展开至 48 像素，或再次折叠。“视图”提供全部折叠／展开，以及 36、48、64 像素展开行高。滚轮、双指纵滑或右侧滚动条上下浏览轨道；双指横滑、中键拖动或底部滚动条左右浏览时间。Ctrl+上下滚轮围绕鼠标缩放。

五轨不增加时间线的最低高度。预览与时间线仍可自由分配高度；紧凑布局通过轨道滚动访问下方内容。

## 创建与修改

| 对象 | 创建 | 修改 |
|---|---|---|
| Tap / Hold | 前两轨点击／横向拖画 | 原有移动、端点、批量属性与 F/J 录制 |
| Tuning | 在绿色双 Hold 重合区横向拖画；默认两节点、60° | 拖身体移动，拖端点改首／尾，拖内部节点改时间 |
| Ghost | 在 Tuning 覆盖时刻点击 | 调整命中 tick、数量 1～16；同刻可分多批 |

Tuning 绑定同侧所属 Hold 和另一侧支持 Hold，整条路径必须在两条 Hold 的交集中。同侧路径不能重叠，允许首尾相接。窗口外或同侧重叠的新建操作不提交；父对象修改导致既有内容失效时保留问题定位，允许保存稿件。

选中 Tuning 展开“角度路径”。圆周把手修改角度，Shift 精细拖动，输入框可精确填写。共用固定 1920×1080 设计画布的右上射线为 0°，顺时针为正，与窗口比例无关。节点之间以 tick 线性插值角度，沿短弧连接；变 BPM 仍由共同 TempoMap 换算。

单选一条 Tuning，可在属性中关闭“自动半径”，用“半径（px）”设置轨道中心线到画面中心的距离。关闭自动时取首段原半径；输入正数，箭头每次微调 1 px。整条路径的所有分段共用该值，生死两侧分别设置。单位为 1920×1080 设计像素，窗口缩放时随画布缩放；轨道宽度、文字和端帽保持原尺寸。半径编辑支持撤销、复制、恢复和导出，正式内嵌预览同步更新。

双击选中的路径，或把播放头放在内部后选择“在播放头添加转折点”，进入加点候选。调整角度至有效后点击“应用节点”。至少保留首尾两个节点，内部节点可删除；节点时间不能交叉。修改整体结束位置按比例调整内部时间，拖尾节点只改变最后一段。

圆盘上的两个卡槽对应生死角色连线。生侧只能使用右上半圆，死侧只能使用左下半圆；拖动到卡槽即停止，数值输入越界也会停在最近边界。已有越界路径保留为问题稿，定位到具体节点，不自动改写。

当前游戏几何要求每一段跨度至少 28°，上限按规则频率范围计算，当前约 97.63°；累计频差也必须容得下。这些跨度限制仍以问题提示反馈，不自动修改整条路径。折返、多次转向可以通过增添节点编排。

## Ghost 关系与 BOSS

Ghost 横向位置是命中／计分时刻，`Ghost ×N` 表示同一时刻的一批。单侧覆盖关联单侧，同时有生、死 Tuning 时关联双方；同侧衔接点优先刚结束的路径。点击同刻叠放的批次可选择对象；已选批次可以直接拖动，双击可重新打开选择列表。“此刻再添加一批 Ghost”可安排不同来源和数量。

选中内容会高亮关系，右键“选择关联内容”可明确选出整组。移动 Hold 带动归属它的 Tuning，不隐式移动支持 Hold；共同 Ghost 仅在双方 Tuning 都移动时随动。所有对象只移动一次。直接拖动 Ghost 按新位置匹配关系；父对象移出窗口保留旧引用并显示问题，可用“按当前位置重新关联”修复。另一侧新条覆盖已有有效 Ghost 时，在同一次命令中补上共同关系。

缩短或删除父对象时，弹窗列出受影响内容：保留并标出问题、删除受影响内容、取消。不会自动裁剪节点或减少数量。复制完整关系时重映射事件、节点及组合 ID；部分复制尝试在目标位置匹配父对象，找不到则保留为问题稿。

右键或属性中的“BOSS 发出”对 Tap、Hold、Ghost 生效，一批 Ghost 共用标记；混合选区跳过 Tuning。标记只改变显示、保存和历史，不触发玩法编译，不影响目前游戏行为。

## 共同 JSON v2

歌曲清单继续 `minghe-song` v1；谱面为 `minghe-chart` v2，与 Resource 的 `schema_version` 无关。读取 v1 不自动改文件，显式保存写 v2 并沿用 `.bak`。未知字段保留在原对象、节点上。项目和 ZIP 使用同一份数据，旧程序若只认识 v1 需要更新共享加载代码。

| 数组／字段 | 类型与含义 |
|---|---|
| `notes[].boss` | 可选 bool，默认 false；Tap/Hold 来源 |
| `tuning_paths[].id / affinity / tick` | 稳定 ID、生 `zhu`／死 `xuan`、整数起始 tick |
| `hold_id / support_hold_id` | 同侧所属 Hold、另一侧支持 Hold 的稳定 ID |
| `tuning_paths[].visual_radius_px` | 可选有限数值；缺失或 0 为自动，正数为整条路径共用的设计像素半径；负数报问题 |
| `points[].id / offset_ticks / angle_deg` | 节点 ID、相对起点整数 tick、角度；首节点偏移 0，严格递增 |
| `ghost_events[].id / tick / count` | 批次 ID、整数结算 tick、数量 1～16 |
| `tuning_ids` | 一条或两条 Tuning 的 ID，同侧只关联一条 |
| `ghost_events[].boss` | 可选 bool，默认 false |

Tuning 时长由末节点求出，不保存第二份总时长。频率、场域、预测坐标和运行时成绩不进入新编排数据。完整可解析示例见 [normal.json](../tests/editor/fixtures/tuning/charts/normal.json)。

示例 BPM 120、首拍偏移 0、全谱偏移 0，因此一秒为 960 tick：

| 编排 | 音频时刻 | 说明 |
|---|---|---|
| 生 Hold / 死 Hold | 2～8 秒 / 3～9 秒 | 双 Hold 窗口 3～8 秒 |
| 生 Tuning | 3.5、5、7 秒 | 三节点往返 |
| 死 Tuning | 4、5.5、7.5 秒 | 三节点往返，不等时长 |
| Ghost | 4.5 秒 ×2；6 秒 ×3 | 两批共同关联，后一批 BOSS |

## 当前规则预览的边界

`ChartPathAdapter` 把新路径临时投影成当前频率滑条，每两个相邻节点一段；场域来自完整双 Hold 交集，节点间频率连续。投影只用于游戏编译及预览，绝不回写 JSON。预览和 `ChartProjectLoader.load_stage(song.json/ZIP)` 共用此入口。

`StudioPreviewInputs` 只对真实 Tap/Hold 生成敲钟按下、松开，Tuning 追加位移采样。同刻先完成旧段尾点再开始新段，Hold 与 Tuning 同尾时在尾点结算后松键。仍使用正式模拟，定位无声恢复、唯一 Transport 与过期请求取消保持有效。

当前旧游戏有以下差异，不能用预览结果替代最终验收：

- 多节点路径仍由独立分段表现；自动模式保留各段原半径，自定义半径使各段位于同一圆周、节点接合位置一致。预告与段间切换仍沿用当前表现。
- Ghost 暂走独立素音显现入口，可能找不到足够交点；属性显示已结算批次的实际生成数量。
- 已支持在真实交点池中随机抽取指定数量；新版使用整幅画面，旧谱显式区域保留。候选不足时不提前冻结，命中时仍不足会显示“交点不足”。当前没有新规则的理想状态预测、共同等级和固定数量独立计分；旧滑条仍按旧规则计分。
- BOSS 不进入游戏行为。旧 `.tres` 的频率调频、旧素音继续归档，不声称等价迁移。

游戏侧交接见 [职责说明](tuning-su-game-editor-handoff-2026-09-08.md)，验证与性能见 [本轮记录](chart-editor-tuning-validation.md)。

波形带为 24 像素，连同秒尺、节拍辅助尺和注释行共 72 像素。首拍标记保留拖动，详细时间可悬停查看；BPM 与段落共用注释行。Ghost 使用独立灰白色系轨道底色，与生死两侧区分。
