# 触摸板与时序优化记录（2026-09-08）

本轮从 `editor` 分支的 `4c17cb5` 开始，保持共同 JSON 协议、判定窗口、Hold／调频规则和编钟音色。用户 test 工程仅作只读比较，没有应用新 BPM、偏移或重新生成音符。

## 时间线浏览

时间线接入左右滚轮及 PanGesture。滚轮每单位 100 逻辑像素，PanGesture 每单位 32 逻辑像素；保留 factor 小数，最终换算为浮点秒。每帧合并输入，有横向时只使用横向，Ctrl＋上下滚轮按连续量围绕鼠标缩放。系统事件决定方向，不再附加惯性。

手动浏览暂时解除跟随，不定位播放头、不改变音符或历史；编辑手势期间忽略浏览输入。还修复了视口较远时相对浮点近似判断吞掉微小滚动的问题。32 项实际 Viewport→Control 事件分发检查通过，覆盖 100%／125%／150% 控件缩放。真实触摸板硬件的不同驱动与系统手势仍需人工检查。

## 提示与预览

旧实现等 Transport 显示已经听到拍点后，再从渲染帧调用播放声音；声音还要等待下一次混音和输出。工作区父节点又先于音频子节点处理，预览消费上一帧时间。这两项会叠加为听感上的迟响，不能用整体提前歌曲来抵消。

现在音频取样优先于工作区，时间线、录入候选和正式预览使用同帧位置。F/J 输入回调当场取样，不再沿用上一帧播放头。歌曲名称、外观等原有轻量更新保持；音符编辑后的预览重演也不再暂停或重启音乐，恢复完毕后无声追上当前时间。

编钟起手和节拍器由 `StudioCueTrack` 提前生成 PCM，排入约 100 ms 的 AudioStreamGenerator 队列。音乐仍走独立保音高总线；提示保持原音高，并复用正式关卡生／死钟素材。音乐处理延迟加入提示样本位置，共同的设备输出延迟不重复加入。设备延迟在启动／重新建立播放段时缓存，不每帧查询。

PCM 预填在驱动锁外完成，两路播放器在短锁内复位／注册，首块写入后初始化 Generator 重采样缓存。环形缓冲使用实际可写容量，不把设置的秒数当作精确容量。已经提交的样本保持不变，编辑版本接管后续样本；过期事件不补播。正式预览关闭重复的起手敲钟，持续与判定反馈单独控制。

定位、倍率及有效循环回绕会重建两路基准，清除旧提示和音乐 PitchShift 状态。无效循环范围不截断提示；循环终点后的提示不会预填；负时间可以先试听提示，跨音乐零点后启动音乐。实测还发现曲尾播放器停止与 finished 信号之间的间隙会误触发再次播放，现已限制只有负预滚跨零才启动尚未播放的音乐。

初版由主线程填队列，在 115／119 ms 长帧中出现欠载。实测后改为常驻线程：`StudioCueMixer` 是独立 RefCounted，只处理有序事件、只读 PCM 与 Generator；节点播放、设备切换和 UI 留在主线程。约每 5 ms 补充样本，状态交接用短 Mutex，原生环形缓冲读写另用短驱动锁，生成 PCM 不持驱动锁。停止旧 producer 必须先于双路启动的驱动锁，退出时等线程结束再释放数据。

线程版人为阻塞主线程 150 ms 和 1.5 秒，11/11 脉冲完整、0 欠载、1 次启动，双路最大偏差 0.042 ms。它隔离了 UI 长帧，但不保证整机调度饥饿或长时间锁住音频驱动时仍不断音。真正欠载时会重新对齐两路并提示，测试分别统计欠载和重建次数。

## 拟合与玩家校准

固定 BPM 改为局部稳定窗口估速、半速归一化及有支持的速度簇；小节位置使用独立参考拍。原始模型缓存与拟合版本分开，重新拟合不加载模型。界面显示已应用值、候选、分段有符号偏差、趋势与覆盖，保持输入精度。详细 test 对比见 [拟合复核记录](rhythm-fit-2026-09.md)。新候选前段更贴近检测，但后段仍存在相位差；没有人工真值，不能宣布整曲识别更准。

正式游戏仍由真实有效输入敲钟，不预先演奏；“起手—声波传播—接触击破”保持原时刻。校准用固定样本参考音、4 拍准备和 24 次跟拍，显示中位早晚、离散程度、设备信息，支持重测／应用／重置。跟拍只建议输入补偿，输出与画面仍独立手调。完整测量与边界见 [玩家反馈与校准记录](game-audio-calibration-2026-09.md)。

## 验证与交付边界

线程版完整脉冲矩阵覆盖两种源采样率、五档倍率和三个帧率上限，共 30 组／150 脉冲：全部出现、0 欠载，每组只启动一次；按 5% 起音阈值计算，双路最坏偏差 2.375 ms。详细录音摘要见 [测量数据](chart-editor-cue-measurement.json)，此前主线程版本失败现场保留在 [基线数据](chart-editor-cue-main-thread-baseline.json)。

原始生／死钟各测五档倍率，共十组，最大双路偏差分别为 4.250／7.021 ms；改用 10% 起音阈值复核，最坏为 7.917 ms。五分钟实时间播放的 6 个首尾脉冲全部保留、0 欠载、1 次启动；音乐与提示固定相差两个 48 kHz 采样（0.0417 ms），首尾漂移为 0 个采样。连同主线程阻塞试验，最终 42 组共 217 个提示事件均出现，没有欠载或无意重启。测试设备实际输出为 48 kHz；两种源采样率和帧率上限不能代替另一输出设备或稳定 144 FPS 的验收。

五分钟、一万音符的完整状态恢复仍是主要热点。本机本轮测得插入 128.4 ms、预览装配／编译 1437.3 ms；定位 0／150／299 秒为 393.3／18335.6／40389.0 ms，普通推进一次 18.8 ms。它仍超过编辑反馈目标；此次不改判定系统，也不通过跳过历史来缩短恢复时间。录音任务同时运行，以上数字记录实际环境，不与空载结果直接比较。

新增提示模块经过排序和二分索引优化：一万音符生成提示事件 24.17 ms、排序及末段定位预填 17.53 ms、33 ms 音频块渲染 0.30 ms。主线程排序外计算、短锁换入；原先脚本比较与逐项定位为约 82—102 ms。完整视觉重演不再拖住音频 producer，但谱师仍会看到“正在定位…”；这项等待没有被隐藏。

- 新版写谱器测试入口包含 12 组套件，新增触摸板、样本队列、同帧预览、精度焦点及拟合测试。Python 拟合 10 项通过。测试使用隔离恢复稿及示例，不覆盖用户工程。
- 正式领域回归仍为核心 1/131、调频 6/101 既有失败，具体失败集合没有扩大。未通过修改规则让测试变绿。
- 玩家校准及输入模式回归 142 项通过。内部注入到声音请求中位耗时，30 FPS 由 31.56 降至 13.87 ms，60 FPS 由 14.87 降至 5.56 ms；这只覆盖软件链路，后续混音与物理输出另计。
- 总线录音绕过模型比较已知脉冲，分别记录源采样率、真实输出率、实际帧耗时、五档倍率、起音阈值敏感性、欠载和重建。总线同步不代表真人按键或蓝牙端到端延迟；44.1 kHz 源不等于 44.1 kHz 输出设备验收。
- 输出缓冲保持原请求值，未凭一次低延迟录音改成 10 ms。外放、有线、蓝牙的端到端闭环及欠载压力对照需要实物测量。
- 完整 Windows 开发包仅导出写谱器，并附带新版识别器、本地 final0、依赖许可、使用说明和示例；显式打包，不包含用户 test／测试工程，不另行导出正式游戏。
